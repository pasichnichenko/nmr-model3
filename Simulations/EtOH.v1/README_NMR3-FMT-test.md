> **Назначение — проверка тракта «массив + параметры → файл, читаемый Mnova», а не физическая точность спектра.**

## 3. Что проверять после открытия в Mnova

Порядок важен: каждый пункт проверяет отдельное звено тракта.

1. **Файл вообще открылся, видна ось ppm.** → структура NTUPLES и таблицы `(X++(R..R))` разобраны.
2. **Спектр не зеркальный:** CH₃ (самый высокий, 3H) — **справа**, около 1 ppm; OH (1H) — **слева**, около 4.6 ppm.
   Если наоборот — знак мнимого канала противоположен ожидаемому. Лечится флагом `CONJUGATE = True` в генераторе. Это одна из трёх ошибок, дающих внешне правдоподобный, но неверный спектр.
3. **Фаза:** после FT спектр должен быть уже в поглощении, автофазировка почти ничего не меняет. → `GRPDLY = 0` отработал, циклического сдвига ССИ не было.
4. **Положения:** 1.06 / 3.44 / 4.63 ppm.
5. **Расщепления:** триплет CH₃ — 7.0 Гц (**0.32 ppm** на 21.7 МГц), триплет OH — 5.0 Гц (0.23 ppm). Наглядно показывает, во что превращается J-константа при низком поле.
6. **Интегралы 3 : 2 : 1.** Мой контрольный расчёт с окнами 0–2.2 / 2.7–4.15 / 4.15–5.4 ppm даёт **2.96 : 1.95 : 1.00** (файл LW 1.2 Гц) и **2.88 : 1.84 : 1.00** (LW 8 Гц). Недобор — обрезание лоренцевых крыльев окном интегрирования, а не дефект данных.

SNR по реальной части: ~1800 (LW 1.2 Гц), ~980 (LW 8 Гц).

## 4. Открытый вопрос: чем Mnova референсирует ось

В JCAMP-DX **нет надёжного стандартного места для «частоты нуля ppm» у данных класса FID**. Поэтому:

- В основные два файла несущая поставлена **точно на 0 ppm** (`O1 = 0`, `SFO1 = SF = BF1`). При таком выборе шкала выходит верной при *любой* трактовке — и если ридер честно берёт `##$SF`, и если он наивно считает `##.OBSERVE FREQUENCY` частотой нуля.
- Файл `..._o1test.dx` — тот же спектр, но несущая на 2.85 ppm. **Это и есть эксперимент.**
  - пики на 1.06 / 3.44 / 4.63 → Mnova разобрала `##$SF` / `##$O1`, референсирование переносимо;
  - пики на **−1.79 / +0.59 / +1.78** → Mnova приняла несущую за 0 ppm; тогда в реальном приборе либо держать `O1 = 0`, либо референсировать вручную, либо переходить на Bruker-формат.

Результат этой проверки — то, ради чего набор и сделан. Его надо записать в `NMR3-FMT`.

## 5. Оговорки

- Точное поведение конкретной сборки Mnova на JCAMP-DX я проверить не могу — структура файла построена по спецификации JCAMP-DX 5.01 (класс NTUPLES) и по конвенции экспорта TopSpin, включая приватные метки `##$…`. Считать рабочей гипотезой до первого открытия.
- Кодирование чисел — **AFFN** (обычные целые + общий `##FACTOR`), не ASDF. Проще и надёжнее разбирается; цена — размер файла ~37 КБ на 2048 комплексных точек.
- Целочисленный round-trip (запись → чтение своим ридером → сравнение с исходным массивом) даёт относительную ошибку **2.6·10⁻⁹**, то есть кодирование данных потерь не вносит.
- Если JCAMP не пойдёт — второй заход делать сразу на **Bruker-папку**: её ридер в Mnova зрелее, и там `SF` / `OFFSET` в `procs` описаны однозначно.
